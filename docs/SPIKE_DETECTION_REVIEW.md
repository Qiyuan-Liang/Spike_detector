# Spike detection workflow review

Reviewed 2026-09-13 against the working-tree GUI version 3.6.14, before replacing two-step detection in 3.6.15. This is a code and methods review, not a measured accuracy comparison: no paired ground-truth electrophysiology or manually adjudicated benchmark was supplied. Existing unrelated working-tree edits and analysis notebooks were left untouched.

## Assessment

This is a useful, inspectable detector for already extracted, single-cell voltage-imaging traces, especially a Purkinje-cell CS/SS workflow. Its strengths are explicit preprocessing controls, robust noise estimates, separate CS/SS streams, threshold and template alternatives, visualization, and settings-rich exports. It is not an end-to-end movie processing pipeline or an extracellular spike sorter. The most valuable next work is input/time validation, explicit artifact masks, event-centered waveform measurements, and ground-truth calibration—not simply a more complex detector.

## What actually runs

1. **Load sessions.** The main folder loader examines top-level CSV, XLSX and NPZ files, without recursively entering subfolders. Tables use column one as time and subsequent columns as cells; Excel prefers Sheet1, falling back to the first sheet. Time spacing heuristically determines seconds versus milliseconds and sampling frequency. Non-numeric time rows are removed; nonfinite trace entries are filled with column medians. NPZ loading extracts raw data, time, names and sampling rate, rather than restoring all prior detection results. See `utils/session.py`.
2. **Preprocess every cell.** `MainWindow.run_detection_all` applies the selected frame-processing mode, then the GUI median/percentile/disabled baseline. Baseline windows are capped by recording length and at 5,000 samples. Optional adaptive wavelet denoising is applied to the SS detection stream, and optionally CS. Polarity inversion makes expected spikes positive. Baseline/denoise exceptions can silently fall back to an uncorrected or undenoised trace.
3. **Threshold mode.** `utils/processing.py::process_cell_simple` filters the CS stream with zero-phase Butterworth filtering, estimates Gaussian-scaled MAD noise, finds positive peaks above a sigma multiplier, enforces CS spacing, applies a minimum width criterion, and excludes an initial interval. It then filters SS, zeros a window around each CS, estimates SS noise, and detects SS peaks with their own threshold and spacing. Optional local thresholds use a rolling-median residual noise estimate. The GUI finally applies the optional SS maximum-FWHM filter.
4. **Template mode.** `process_cell_template_matching` resamples the score computation to at least 5 kHz; templates are resampled and length-normalized. `_llr_probability_vector` computes a Gaussian log-likelihood ratio using template means and diagonal variances against a scalar background noise model. With at most nine templates, the template variance is replaced by the background variance. Peaks in the score are selected using sigma-times-MAD thresholds, spacing and initial blanking. CS score peaks also receive a minimum-width filter. CS windows are zeroed before calculating SS scores. Results are rounded back to acquisition samples. Parallel matching clusters templates using PCA/k-means, retains up to three groups, and unions group detections with detections from the maximum score trace.
5. **Former two-step mode.** The old button forced template matching, also ran threshold detection, and retained template detections supported by nearby threshold detections. It was an intersection of two detectors using much of the same signal processing, not independent confirmation or measured error control. Its extra six-panel viewer has been removed in 3.6.15, as requested.
6. **Statistics and output.** Final results are held per session/cell. Exports contain raw and processed traces, baselines, CS/SS streams, times, event metrics, waveform arrays and JSON settings; a companion settings JSON includes template settings. Override-off routes repeat results into `_temporary_detection`. Info averages rates across session-cell entries; SNR and widths pool valid events. Statistics generally use frame-processed, baseline-corrected original traces rather than wavelet-denoised traces, while CS FWHM uses the CS stream. Thus “raw waveform” statistics can still depend on smoothing and baseline choices.

## Findings and recommended corrections

| Priority | Finding from the code | Consequence and recommendation |
|---|---|---|
| High | `normalize_time_and_fs` switches units at median spacing 0.01; time-vector origin and regularity are not rigorously validated. Exports derive event times from index/fs. | A 100 Hz table in seconds has spacing 0.01 and can be interpreted as milliseconds; nonzero origins or dropped frames can misalign event times. Require explicit time units or a confirmed import preview; validate finite, strictly increasing, sufficiently regular time, and derive timestamps from the recording time vector under a documented origin convention. |
| High | Table loading silently removes bad time rows and fills invalid trace samples. | Dropouts can become artificial discontinuities, alter elapsed time assumptions, or look like clean measurements. Preserve a validity mask, show repairs and exclude neighborhoods affected by filtering. Reject wholly invalid channels. |
| High | SS blanking is centered on CS, despite text saying “after CS”; zeros enter the signal used for SS detection. | Real pre-CS SS events are removed. Artificial edges and local-noise collapse can influence nearby events. Expose separate pre/post windows, maintain a boolean exclusion mask, and estimate noise on unmasked samples. Treat the CS-associated SS pause as a biological outcome only outside imposed censoring. |
| High | Widths need not describe the selected event. `get_wave_stats` chooses the largest peak anywhere in the extracted window. | In a 50 ms SS window, a larger neighbor can determine width and reject the wrong event. Anchor peak/half-height crossings to the candidate, constrain the search between neighboring events, and flag overlapping/clipped events. Keep failed-width flags rather than silently treating unknown widths as passing. |
| High | Template-mode CS width filtering operates on the LLR score, whereas threshold-mode width operates on the filtered signal. | A shared “CS FWHM” parameter does not mean the same thing in both modes; changing template length changes score width. Classify morphology on a consistent, candidate-centered trace and label any score-width criterion separately. |
| Medium | The “LLR Probability Vector” is a log-likelihood ratio, not a posterior probability. The model ignores temporal noise covariance; filtering and upsampling introduce correlations. | Do not interpret the score or its MAD multiplier as calibrated confidence or false-positive probability. Rename the score, consider noise whitening, and calibrate acceptance on held-out recordings. Sigma multipliers are not directly comparable across threshold and template modes. |
| Medium | Parallel template candidates are unioned after each group enforces its own minimum distance. | Different groups can leave distinct, closely spaced detections after union. Apply one final score-ranked refractory suppression across the union, with an explicit rule for CS/SS overlaps. Retaining only the largest template groups can also lose rare morphologies. |
| Medium | Baseline windows and smoothing can overlap spike duration; filter cutoffs can be silently clamped or filtering disabled for invalid combinations. | Broad CS can be attenuated by a short baseline, and SS can be broadened by averaging. Validate effective settings per sampling rate, show warnings for invalid bands, and benchmark baseline/denoise choices on amplitude, width and timing—not only visual smoothness. |
| Medium | Noise comes from whole traces or approximate local rolling MAD; local windows can include substantial spike activity and zeroed intervals. | Noise can track firing rate instead of acquisition noise. Estimate it iteratively on spike/artifact-masked residuals, keep a floor derived from real background samples, and expose the estimated noise over time. |
| Medium | Rate denominators use recording span, including the initial blank and excluded time. Cell means treat each session-cell equally. | Short recordings and different mask burdens may not be comparable. Export total duration, analyzable duration and censored duration, plus both observed whole-recording rate and explicitly labeled valid-time rate. Report path/session/cell counts and distinguish event-weighted from cell-weighted summaries. |
| Medium | Statistics recompute preprocessing using current GUI controls; detection settings may have changed since the run. Event metrics can omit invalid events independently. | A displayed metric can differ from the saved run. Bind viewer statistics to an immutable detection snapshot, and export a per-event table keyed by path/session/cell/type/sample index with NaN and quality flags instead of removing invalid entries. |
| Engineering | The GUI contains legacy local copies of processing helpers that are subsequently rebound to imports from `utils/processing.py`. Broad exception handlers hide failures, and runs execute on the GUI thread. | Consolidate the duplicated code in a separate refactor, use structured per-session/cell errors, and move compute into a worker with progress/cancellation. Batch 3.6.15 improves error visibility and prevents controls changing during computation, but remains synchronous and memory-resident. |

## Comparison with established approaches

**Voltage imaging: VolPy.** VolPy includes movie-level spatial/background processing and iterative temporal spike estimation using adaptive thresholds and whitened matched filtering. Your GUI starts after cell traces have already been extracted. Consequently, it cannot recover spatial demixing or motion/background contamination solely by tuning temporal thresholds. Your explicit CS/SS morphology rules are useful for this specialized preparation, but are not independently validated classification. The most transferable VolPy ideas are background-aware extraction upstream, noise whitening, and fitting templates from confident events before re-estimation. Validate each addition against the simple threshold baseline. The removed two-step function should not be confused with VolPy’s iterative matched-filter procedure. [VolPy paper](https://pmc.ncbi.nlm.nih.gov/articles/PMC8075204/).

**Intracellular electrophysiology: AllenSDK.** AllenSDK detects putative action potentials through dV/dt, then checks height, peak level, threshold-to-peak consistency and overlapping events. Your detector emphasizes optical peak amplitude/template shape rather than electrical onset. Transfer the principle of candidate validation and explicit onset/peak definitions, but do not transfer mV, V/s or kHz thresholds directly to fluorescence. Indicator kinetics and camera sampling affect the observable waveform. A derivative feature could complement optical detection only after noise-aware validation. [AllenSDK feature extraction](https://alleninstitute.github.io/AllenSDK/allensdk.ephys.ephys_features.html).

**Extracellular electrophysiology: SpikeInterface.** Extracellular pipelines must assign multichannel events to units; an extracted ROI already supplies a tentative cell identity, so adding a full spike sorter is not automatically helpful here. SpikeInterface’s quality metrics include SNR, ISI/refractory violations, presence and other unit-quality measures. Transfer temporal stability, missingness, residual and event-quality reporting. Refractory checks should be diagnostic: an algorithmically imposed minimum distance makes a clean short-ISI histogram partly circular, rather than proof of clean detection. [SpikeInterface quality metrics](https://spikeinterface.readthedocs.io/en/stable/modules/metrics/quality_metrics.html).

## Suggested order of improvement and validation

1. Correct time handling, candidate-centered widths, masking semantics and effective-setting validation first. These affect scientific interpretation independently of detector choice.
2. Build a labeled evaluation bank stratified by animal/recording, CS versus SS, indicator, SNR, firing rate, motion, bleaching and overlapping events. Prefer simultaneous electrical ground truth; use blinded expert adjudication where unavailable and label its limitations. Split templates and tuning by recording/animal to avoid leakage.
3. Compare threshold, current LLR, and a whitened matched-filter candidate under identical preprocessing and masks. Report precision, recall, F1, false events/minute and timing error with a prespecified optical timing tolerance; report CS/SS confusion, collision performance and per-recording uncertainty. Sweep thresholds to compare at matched precision rather than comparing arbitrary sigma values.
4. Test injected templates in real noise over amplitude, width and noise drift, but keep synthetic recovery distinct from biological validation. Include nonzero time origins, seconds/ms tables, irregular timestamps, gaps, short traces, empty templates and template transfer between recordings.
5. Only then consider learned classifiers or more elaborate denoising. A higher SNR after denoising is insufficient evidence: measure missed spikes, timing bias and morphology distortion.

## Implemented scope in 3.6.15

Two-step detection and its viewer branch are removed. Batch detection accepts pasted paths, repeated folder selection or a UTF-8 text list (one folder per line; relative imported entries resolve against the list file). Duplicate paths are collapsed; invalid files and unavailable/empty folders are reported. All loaded sessions use the same main-GUI parameters, templates, frame processing, baseline, polarity and denoise controls. Each source folder receives its own outputs under the existing override policy. Info covers all requested paths and pools completed sessions. Spike Statistics adds Path → Session → Cell with All scopes. No detection algorithm or analysis notebook was changed as part of this feature.


## Validation of the batch change

Eight offscreen PyQt6 regression tests passed using synthetic recordings in temporary directories. They cover single-versus-batch spike-index equality, per-folder exports and identical analysis settings, repeat-output preservation, override-on behavior, same-stem input collisions, duplicate and unavailable paths, nonrecursive discovery, relative path-list import, Path/Session/Cell filtering, template-mode execution, and recovery/reporting for processing and save failures. The ordinary four-panel detection viewer, batch dialog and statistics window were rendered; screenshots of the main GUI, batch dialog and statistics were visually inspected. These checks establish feature behavior, not biological detection accuracy. No user recording was processed or overwritten.


## Follow-up: 3.6.16 scientific corrections (2026-09-14)

The first four recommended corrections have now been implemented. The findings above describe the original 3.6.14 behavior and are retained as the audit record. See README’s “Time, widths and exclusions” section for the new import, measurement, masking and validation contract. The change uses explicit units and rejects malformed inputs rather than attempting automatic repairs. Candidate widths and their validity are saved once and reused in summaries; unknown widths remain detected with flags. Baselines are estimated from robust edge samples inside the candidate’s bounded neighborhood, taking the lower boundary estimate for positive-going waveforms when one side is contaminated. This is a transparent estimator, not a deconvolution of overlapping events. Template alignment is limited to 2 ms and does not redefine exported candidate timestamps; the aligned waveform peak is recorded separately.

Rates remain full-recording rates, now using samples/fs; exported validity masks and analyzable durations permit separately labeled valid-time analyses. A template must not draw on an excluded interval, so its support expands exclusion around CS and the initial blank. Existing amplitude/SNR algorithms otherwise remain distinct from width measurements. Ground-truth calibration, motion/background extraction, model calibration, and a worker-based asynchronous detector remain future work.

Validation: all 25 batch/scientific regression tests passed, including a GUI-level check that the 2 ms event survives while its 5 ms neighbor fails the 3 ms maximum-width rule. Offscreen rendering verified the main time-unit selector, statistics uncertainty/valid-time summaries, and Advanced Settings pre/post mask controls. Tests used temporary synthetic data only.

## Follow-up: 3.6.18 template matching and responsive detection (2026-09-27)

The review above records the earlier 3.6.14 implementation. In 3.6.17 the template branch gained normalized Pearson similarity, a short SS core, explicit masks and response/width checks. In 3.6.18 both methods remain available in the same main-GUI and batch code path. Batch captures the current method, CS and SS banks, filters, thresholds, baseline, frame processing and masks for each cell. If only one template type is loaded, its counterpart has a zero score track and no events. Each bank can be cleared independently.

The former **LLR Probability Vector** implementation used the pooled template mean and per-sample variance at their original amplitude against a scalar Gaussian noise model. A dim cell could receive a low or negative score despite matching the temporal shape; score-MAD thresholds were also unstable when the one-sided null score had many zeros. The revised branch fits a nonnegative amplitude at each candidate. With a unit-norm template `u`, filtered trace `x`, and unmasked cell noise estimate `σ`, it uses `z = max(0, <x,u>)/σ` and displays `z²/2`, the Gaussian log-likelihood gain over zero amplitude under a white-noise approximation. The GUI σ cutoff corresponds to `z ≥ cutoff`; it is **not** a posterior probability, threshold-mode σ, or the old score-MAD multiplier. The SS branch uses a 3 ms core; CS uses its full waveform. A CS candidate also needs a 3×MAD local deflection and full-shape Pearson `r ≥ 0.6`. An isolated SS candidate whose full template window is unmasked needs weak full-shape `r ≥ 0.5`; candidates within 8 ms of another score candidate bypass that extra check so a burst with truncated tails can survive. Normalized Similarity uses the same short SS core and response checks, with its own Pearson-r thresholds.

The displayed CS and SS score lines are **candidate cutoffs**. A local score maximum can subsequently be lost to the initial/CS/support mask, response or shape check, refractory spacing, or candidate-centered width filter. In parallel mode, three populous template subgroups are tested separately and final candidates compete across groups; the viewer plots each group’s score above its own cutoff, so zero is the displayed line. The viewer now shades excluded score regions and gives per-cell rejection counts. CS and SS scores are independent evidence streams, not mutually exclusive class probabilities: the rapid CS leading edge can match the short SS core. A detected CS masks surrounding SS candidates, but its SS score can still be high on the plot. A CS missed by the CS bank can still be mistaken for SS; inspect the raw width and morphology before treating such events as SS.

The supplied 3,333 Hz, 17-cell CSV and its saved template banks were evaluated read-only. For the four screenshot cells, approximate blue-marker times were mapped from image coordinates into their stated 1 s viewer windows. At the new SS matched-SNR cutoff 3, 25 of 37 marked misses were within ±5 ms of a surviving SS candidate after the 0.8–3 ms width rule; the same four windows contained 260 candidates. At cutoff 2, recovery rose but event counts approached 100 per second per cell, and polarity-reversed traces also yielded many events. These are exploratory checks, **not** precision, recall or a false-discovery estimate: the screenshots mark misses, not all true and false events, and pixel-to-time mapping is approximate. The default is 3 for sensitivity; review weak additions cell by cell and raise it if false events dominate. In this sample, parallel mode at cutoff 3 recovered fewer blue marks (23/37) while generating more candidates than the pooled mode, so leave it off unless distinct waveform subgroups are verified. A timestamped manual annotation table or simultaneous electrical ground truth is still needed to choose a final operating point.

The main-GUI and batch buttons now schedule per-cell detection and compressed NPZ writing on worker threads. The bottom status bar reports completed cells and saving, while Qt continues handling paint and input events. Preparing export arrays still runs in the GUI thread in chunks with event processing; loading the initial batch folders is also synchronous. The controls stay locked for a run, and the app defers closing until the current run finishes to avoid destroying a live worker.
